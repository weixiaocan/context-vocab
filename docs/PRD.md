> 版本: v0.2
> 日期: 2026-07-13
> 状态: 功能范围已收敛，待进入架构阶段

## 1. 项目背景与定位

### 1.1 业务背景

我每天阅读大量英文 AI 材料（网页文章、书籍、技术文档）。当前状态：

- **能读懂**：借助翻译插件，文章大意基本没有障碍
- **留不住**：阅读中遇到的生词，看过一遍就过去了，下次再遇到仍然陌生

痛点不在"读懂这一篇"，而在"**下次遇到这个词时不再陌生**"。这是一个词汇留存问题，不是阅读理解问题。

**上一版失败的原因**：流程过于复杂，一时兴起开始，没想清楚目的。本次重做的第一原则是——**摩擦是头号敌人**。任何让我"需要专门坐下来学英语"的设计都会死。

### 1.2 项目定位

| 目标 | 优先级 | 说明 |
|------|--------|------|
| **个人日用工具** | **主** | 我每天真的会用。能用起来 > 功能完整 > 工程优雅 |
| **AI 协作开发练习** | 次 | 完整跑通"需求 → 架构 → 开发 → 测试 → 部署"一圈 |

**冲突时的取舍原则**：保工具属性。

但次要目标有一条硬约束：**系统必须小到能跑完全流程**。次目标要的是"跑通一次完整闭环"，不是"做一个复杂系统"。系统越小，越可能真的跑完。上一版的教训已经证明了这一点。

**明确的反陷阱声明**：不要因为"想用上评估方法论/agent 架构"而把确定性流程改造成 LLM 流程。确定性流程一样要测，而且更好测。

## 2. 术语表

| 术语 | 定义 |
|------|------|
| **候选池** | 我主动"加入生词本"的词，等待被放行进入学习。**积压无害**——词在这里躺着不会坏 |
| **复习队列** | 已经开始学、尚未毕业的词。**积压有害**——这些词正在被遗忘，而我够不着它们 |
| **卡片位** | 每天推送的卡片总数（v1 = 10）。这是真正的产能上限 |
| **新词卡** | 该词第一次出现在卡片中 |
| **复习卡** | 该词在复习队列中，尚未毕业 |
| **毕业** | 一个词被正确回忆 N 次（v1 = 3）后移出复习队列，不再推送 |

## 3. 范围定义

### 3.1 v1 范围

| # | 功能 | 含 LLM | 说明 |
|---|------|--------|------|

| F7 | 结果回流与计数 | 否 | 选对次数 -1，选错不变，减到 0 毕业 |
| F8 | 同词去重 | 否 | 追加例句 + 重置次数 |

### 3.2 明确不做

**v2 候选（真的可能做）**
- 语音陪练智能体（基于我读的材料用英语对话 + 事后复盘）。**这是另一个产品，不是本产品的功能。**它与本项目除了"素材同源"外几乎无共享部件。

**永久不做（不再讨论）**
- SRS 间隔重复算法（SM-2 / FSRS 等）—— v1 只用"剩余推荐次数"计数器
- 成就系统、打卡、连续天数、积分
- 原生 App
- 自动过滤 AI 领域黑话 —— 入不入库由我点击决定，不需要机器猜
- 造句练习、写作批改
- 「认识 / 不认识」自评按钮 —— 选择题本身就是判分

## 4. 用户与使用场景

### 4.1 用户

只有我一个。不考虑任何第二用户，不做多用户、不做登录。

### 4.2 典型使用场景

**场景 A：白天，电脑上读英文文章**

1. 读到 `The gains from further scaling appear marginal.`，不认识 `marginal`
2. 划词 → 弹窗显示英文释义、音标、发音按钮
3. 大部分情况：看懂了，关掉弹窗，继续读（**零后续动作**）
4. 少数情况：这个词我想记住 → 点"加入生词本" → 进候选池（连同原句一起）

**场景 B：第二天早上，手机上**

1. 8:00 收到飞书消息："今天有 10 张卡"
2. 点开链接 → 网页
3. **第一层**：`marginal` + 原句 `The gains from further scaling appear marginal.`（词高亮）。我在脑子里回忆它是什么意思
4. 点「看选项」→ **第二层**：4 个中文含义。我选一个，立即知道对错
5. **第三层**：正确答案标出 + 该词的全部英文释义（纯英文）+ 自动播放发音。原句中文折叠着，看不懂时才点开
6. 下一张。10 张刷完，约 5 分钟，关掉

## 5. 功能需求详述

### F1 + F2. 采集（浏览器插件）

- **输入**：我在网页上划选的一个词
- **逻辑**：
  - 划词 → 查词（走缓存或词典 API）→ 弹窗显示释义、音标、发音
  - 弹窗上有一个「加入生词本」按钮，点击后：抓取该词**所在的完整句子**，连同词一起入候选池
- **输出**：候选池新增一条 `{word, sentence, source_url, timestamp}`
- **验收**：
  - 划词到看见释义 ≤ 1 秒
  - 入库 = 1 次点击，无需分类、打标、写笔记
  - 原句抓取准确（不是半句，不是整段）

> **设计要点：入库要贵，复习要贱。**
> 划词看释义是免费的（零摩擦，鼓励多查）；入库要多点一下（有摩擦，逼我筛选）。
> 因为每天只有 5 个新词卡位，见词就点毫无意义。

### F3. 词条补全

- **输入**：候选池中的新记录 `{word, sentence}`（批量，后台跑，不阻塞任何用户操作）
- **逻辑**：
  1. **词典层（确定性，按词缓存）**：查词典 API，取该词的全部释义、词性、IPA 音标、发音音频 URL。**释义保持纯英文，不翻译。**一个词一辈子只查一次
  2. **LLM 层（按记录缓存，一条记录只跑一次）**，输出三样东西：
     - **该词在这句原句语境下的中文含义** → 作为选择题的正确答案
     - **3 个干扰项**（同词性、语义相邻、放进这句话也说得通）
     - **原句的中文翻译**
- **输出**：完整卡片数据
- **关键性质**：补全全部在后台一次性完成。**日常复习流程中零 LLM 调用、零词典 API 调用**，全部读缓存
- **验收**：
  - 正确答案（语境中文含义）抽样 50 条人工检查，准确率 ≥ 95%
  - 干扰项抽样检查：不能出现一眼排除的选项（如给形容词配名词释义、语义八竿子打不着）

> **干扰项质量是这个产品的核心质量。**
> 随便从词库里抽，会抽到"一种红色水果"这种一眼排除的选项，题目就白出了。
> 好的干扰项要似是而非——考 `marginal` 时，干扰项里应该有"可以忽略不计的（negligible）"。
> **同义词辨析恰恰是"认得出"和"用得对"之间的全部差距。**

### F4. 每日组卡

- **触发**：每天 8:00
- **逻辑**（推送那一刻现算，不提前分配）：
  1. 从复习队列中取 5 张（优先取距上次复习最久的）
  2. 从候选池中放行 5 个新词
  3. 不足则有多少给多少，不补齐
- **输出**：今日 10 张卡的列表
- **关键性质**：**没做完的卡片不是"欠的作业"。**它们只是还在队列里，明天可能又被抽到。**不积压、不惩罚、不提醒、不显示"你已断更 3 天"。**

### F5. 飞书推送

- 每天 8:00 一条消息，内含今日复习页链接
- 消息里显示"今天 10 张"
- 复用 AI Radar 已跑通的飞书推送链路，不引入新技术

### F6 + F7. 复习页与回流

**卡片是三层结构，两次点击。信息密度刻意递增——最穷的在前面（逼我自己想），最富的在后面。**

**第一层（考前）：只给最少信息**
- 词：`marginal`，音标
- 原句，词高亮（**不挖空**——要练的就是"在句子里看到这个词能不能懂"）
- 提示：*想一下它在这句话里是什么意思*
- 按钮：`看选项`

**第二层（考试）：4 个中文含义，选一个，立即判分**
- 1 个正确答案（该词在该原句语境下的中文含义）
- 3 个干扰项（同词性、语义相邻、放进这句话也说得通）

**第三层（考后）：这里才是学习的正餐**
- 正确答案标出
- **该词的全部英文释义（纯英文，词典原样）**
- **自动播放发音**（不做成按钮——做成按钮我一次都不会点）
- 原句中文翻译（折叠，可选）

> **为什么词典释义放在考完之后：**
> 考前给一堆释义，我会扫一眼就过去，什么都不留。
> 但在我刚做出判断、尤其是刚答错的那一瞬间，大脑对正确答案的接受度最高——我正带着"我以为是 A"的预期，这时看到"其实是 B"，落差本身就是记忆锚点。
> **先逼我调取记忆 → 再判分 → 再给完整信息。**

**计数逻辑（字段：剩余推荐次数）**
- 入库时 = 3
- **选对 → 次数 -1**
- **选错 → 次数不变**（不归零、不惩罚）
- 减到 0 → 毕业，移出复习队列

> **为什么答错不归零：**
> 归零是惩罚性的——答对两次、第三次卡壳就全清，难词永远毕不了业，在队列里无限循环。
> 而我们已知本项目最大风险就是复习队列积压，归零会主动往伤口上撒盐。
> **进度只前进不后退。**难词会多出现几次，但它一直在朝毕业走。

**不需要「认识 / 不认识」按钮。**选择题本身就是判分。少一个交互，少一次犹豫。

**观测项**：页面底部一行小字显示当前**复习队列积压量**（例如"待复习 47"）。
**只显示，不提醒，不催促，不做任何行为设计。**

- **验收**：10 张卡在手机上刷完 ≤ 5 分钟

### F8. 同词去重

- **规则**：同一个词再次被「加入生词本」→ **不新建记录**
  - 新原句**追加**到已有词条（一对多，不覆盖）
  - **剩余推荐次数重置为 3**
  - 出卡时优先使用最新的那句例句
- **为什么重置进度**（这一条和"答错不归零"看似矛盾，其实不是）：
  - 入库是两段式的——重新入库需要我**主动再点一次**。这不是意外，是一个明确信号：**我在真实文章里又没认出它，之前的"答对"是选择题给的假阳性**
  - 选择题会高估我的水平（从 4 个选项里认出来 ≠ 裸读时认出来）。**真实阅读中的再次划词，是唯一一个真实场景的检验，它有权推翻选择题给的分**
  - 所以重置不是惩罚，是修正一个错误的进度
  - 如果一个词被反复重置，它就该一直待在队列里——那是系统在正常工作

## 6. LLM 使用边界

### 6.1 用 LLM 的环节

**全部集中在补全阶段，一条记录跑一次，永久缓存。三个用途：**

| 用途 | 为什么必须是 LLM |
|------|-----------------|
| **该词在原句语境下的中文含义** | 这是选择题的正确答案。词典返回的是一堆义项，哪一条符合这句话，需要理解句子。规则做不到 |
| **3 个干扰项** | 要似是而非（同词性、语义相邻、放进这句话也说得通）。这是本产品的核心质量所在 |
| **原句中文翻译** | 需要理解上下文并生成通顺中文 |

**成本：几乎为零。日常复习流程零 LLM 调用。**

> **关于义项消歧的立场变更（v0.1 → v0.2）：**
> v0.1 曾把"义项消歧"列为永久不做，理由是"展示全部释义，我自己对照原句判断"。
> 但卡片形态改为**选择题**之后，系统必须知道正确答案是什么，才能判分——**消歧就绕不开了**。
> 这不是加回了一个功能，是卡片形态推出来的必然结果。记录在此，免得以后忘了为什么。

### 6.2 不用 LLM 的环节

| 环节 | 为什么不用 |
|------|-----------|
| 英文释义翻译 | **不译。**卡片第三层展示的是词典原样的纯英文释义 |
| 判断某个词值不值得学 | 我点击就是判断。机器猜不如我点一下 |
| 查词、组卡、抽卡、计数、毕业、去重 | 纯确定性规则 |
| 推送、缓存、存储 | 纯工程 |

### 6.3 工程化要求

- LLM 调用必须可重放、可缓存
- 结果落库，不重复调用
- 有抽样评估机制（见 F3 验收）
- 测试时 LLM 调用必须可 mock，不依赖外部网络

## 9. 风险与开放问题

### 9.1 已识别风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| **复习队列积压**（见下） | 高 | 参数可配 + 积压量可观测，跑一个月用数据决定 |
| **我不打开推送** | **致命** | 唯一防线是低摩擦（5 分钟、手机、一键）。不做提醒、不做打卡——那些是在惩罚我，只会让我更快放弃 |
| **干扰项质量差** | 高 | 干扰项太容易 → 题目白出，什么都学不到。这是本产品最核心的质量指标，必须做抽样评估 |
| **选择题高估我的水平** | 中 | 从 4 个选项里认出来 ≠ 裸读时认出来。部分缓解：第一层"先自己想再看选项"；以及 F8——真实阅读中的再次划词可以推翻选择题给的分 |
| 朗文 API 不可用 | 中 | 已确认 Pearson 开发者门户基本停摆。默认方案改为 Merriam-Webster Learner's（同为学习者词典，用简单词汇解释难词，非商业免费 1000 次/天/key，含 IPA 与发音音频）。**开发前先花 20 分钟验证 key 能否申请** |
| 原句抓取不准 | 中 | 网页 DOM 结构千奇百怪。先做主流场景，不追求 100% |

### 9.2 核心风险详述：复习队列会积压

**这是本 PRD 里唯一一个我明知有问题、但主动接受的设计。**

算术上：每放行 1 个新词，它就预订了未来至少 3 个卡片位（首次露面 + 2 次复习）。5 新 + 5 复习的配比意味着每天新增 10~15 次复习需求，但只消化 5 次。**复习队列会持续净增长。**

数学上"安全"的配比是每天 2~3 个新词 + 7~8 张复习。

**但我选择 5:5。理由：复习占比太高会失去新鲜感，而我不想打开的系统价值为零。动机是这个项目最稀缺的资源，比留存率更稀缺。**

**代价我认**：一部分词会见过 1~2 次后再也排不上队，慢慢忘掉。这不是 bug，是取舍。

**应对**：积压量做成可观测（复习页底部一行小字），参数做成可配。跑一个月后看数据：
- 积压稳定在 30 以内 → 5:5 成立，我的担心是多余的
